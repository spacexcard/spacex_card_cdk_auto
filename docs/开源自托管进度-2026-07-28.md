# CDK 兑换 · 开源自托管进度

> 日期：2026-07-28（修订：后台安全/可配置/安装向导）  
> 目标：把 CDK 兑换做成可开源、可自部署产品——部署方自配 **代理 / 皮肤 / 密钥 / 用户与订单**，管理后台**安全 + 灵活可配置**。  
> 范围：`cdk-recharge-system/`（对接卡台 Open API）。

---

## 0. 产品策略（一句话）

部署者 clone 本仓库 → **首次安装生成管理员（仅一次）** → 在 `/ops` 配密钥/主题/对接 → 自己的用户用 CDK 兑换 → 只看到自己站上的订单。  
我们卖的是**可运行的兑换壳 + 卡台 Open API 对接**，不是把号池/代理白送。

| 能力 | 开源自托管期望 | 现状 | 状态 |

| **管理入口隐蔽** | 非常见 `/admin` | 前端 **`/ops`**，API 仍 `/api/v1/admin/*` | ✅ 路径；可再配自定义前缀 ⬜ |
| **用户体系** | 注册登录、用户只看自己的单 | 有 Login/Register；历史多为 **CDK 码查询** | ⚠️ 半成品 |
| **订单** | 管理端全量；用户端仅自己的 | 管理端有；用户端按 CDK 查 | ⚠️ 半成品 |
| **多租户 SaaS** | 一库多站 | 无 | ❌ 远期 |
| **一键 Docker 开源包** | compose + 文档 | 有 compose，文档偏内部 | ⚠️ |

**结论：开源自托管闭环尚未实现。** 当前更像「内部运营台 + 用户兑换页」，不是完整的可白标产品。  
**下一波核心：后台安全 + 配置中心 + 一次性安装向导（防重放/防二次劫持）。**

## 5. 后台管理优化目标（核心：安全 + 灵活可配置）

### 5.1 设计原则

| 原则 | 含义 |
|------|------|
| **安全默认** | 无硬编码生产密码；release 强制强 `JWT_SECRET`；密钥不进前端包、不进 git |
| **一次安装** | 管理员 bootstrap **只能成功一次**；完成后接口与页面永久不可用 |
| **配置外置** | 主题/品牌/对接密钥/代理策略均可改，不改代码 |
| **最小暴露** | 管理 UI 用 `/ops`；可配置自定义 path 前缀（远期）；敏感字段只写不读或脱敏读 |
| **可审计** | 安装、改密、改密钥、改品牌均写 `admin_audit_logs` |
| **分层配置** | env（启动级）> DB（运行时可改）> 前端 localStorage（仅预览回退） |

### 5.2 可配置矩阵（后台「站点设置」应覆盖）

| 分组 | 配置项 | 存储 | 谁能改 | 前端是否可见明文 |
|------|--------|------|--------|------------------|
| **品牌/界面** | 站名、副标题、Logo URL、favicon | DB `site_settings` | admin | 是（公开） |
| **主题风格** | skin id、light/dark/auto 默认 | DB | admin | 是（公开） |
| **管理入口** | 自定义 ops path（可选） | env 或 DB | 部署时/超管 | path 本身公开，别写在对外 README 大字 |
| **JWT / 会话** | `JWT_SECRET`、过期小时 | **仅 env** | 部署者 | 否 |
| **初始管理员** | 用户名/密码 | 安装向导一次 or `ADMIN_*` env | 安装时 | 密码仅展示一次 |
| **卡台对接** | API base、API key | 同上 | admin | 脱敏 |
| **Telegram** | bot token、chat id | 同上 | admin | token 脱敏 |
| **代理策略** | 不在本站运营 | — | — | — |
| **兑换策略** | dry-run 默认、冷却、计划映射 | DB | admin | 是（非密钥） |
| **注册开关** | 是否开放用户注册 | DB | admin | 是 |

**密钥保险箱规则（B3）：**

1. 写入：HTTPS + admin JWT；body 中明文只走 TLS。  
2. 读出：API 只返回 `configured: true/false` + 末 4 位，**永不返回完整 secret**。  
3. 存储：优先 **env**（12-factor）；若必须 DB，用 `APP_MASTER_KEY`（env）做 AES-GCM 封套加密。  
4. 日志：禁止打印 token/HMAC/卡号/sessionKey。  
5. 轮换：支持「覆盖写入」；无「导出全部密钥」接口。

### 5.3 与现有后端的对齐（避免重复造轮子）

已有能力（应保留并纳入向导）：

| 已有 | 位置 | 行为 |
|------|------|------|
| `ensureDefaultAdmin` | `backend/internal/db/db.go` | 无管理员时：`ADMIN_PASSWORD` 或 **随机 16 位**；bcrypt 入库；随机密码 **只打一次日志** |
| 弱口令告警 | 同上 | 识别历史 `admin123456`，启动告警，**不再用其创建** |
| bcrypt + 旧 SHA 升级 | `HashAdminPassword` / `VerifyAdminPassword` | 登录时静默升级哈希 |
| JWT release 强制 | `enforceJWTSecret` | 空/默认/过短在 release 拒绝启动 |
| 改密 API | `POST /api/v1/auth/admin/change-password` | 需已登录 admin |
| 审计表 | `admin_audit_logs` | 登录/操作可记 |

**缺口：** 无 Web 安装态、无 `install_state`、配置散落 env/localStorage、密钥无统一保险箱 UI。

## 6. 首次安装向导（仅一次）— 防漏洞规格

> 用户故事：部署者第一次打开站点 → 进入安装页 → 点「生成管理员」→ 看到用户名+密码（可复制）→ 确认已保存 → 跳转登录 → **以后任何人再访问安装页无效**。

### 6.1 状态机

```text
  [DB 空 / install_state=pending]
           │
           ▼
   GET /api/v1/setup/status  →  { installed: false }
   前端路由守卫：未安装 → 强制 /ops/setup
           │
           │  POST /api/v1/setup/bootstrap  （仅此一次）
           ▼
   事务内：创建 admin_users + 写 install_completed_at + 审计
           │
           ▼
  [install_state=done]  永久
           │
           ▼
   任何 setup 写接口 → 410 Gone / 403
   前端 /ops/setup → 重定向 /ops/login
```

### 6.2 API 草案（安全）

| 方法 | 路径 | 鉴权 | 行为 |
|------|------|------|------|
| `GET` | `/api/v1/setup/status` | 无 | 只返回 `{ installed: bool }`，**不**返回用户名/是否存在弱密细节 |
| `POST` | `/api/v1/setup/bootstrap` | 无（仅 pending） | 见下；成功后 **立即** `installed=true` |
| 其它 | `/api/v1/setup/*` | — | 安装完成后全部 410 |

**`POST /bootstrap` 请求体（二选一模式）：**

```json
{
  "mode": "generate",          // 或 "manual"
  "username": "admin",         // 可选，默认 admin；长度 3–32，[a-zA-Z0-9_]
  "password": null,            // mode=manual 时必填；generate 时忽略
  "confirm_password": null
}
```

**响应（仅成功当次完整返回密码）：**

```json
{
  "username": "admin",
  "password": "xK7...仅此响应一次",
  "message": "请立即保存密码；本接口已关闭，无法再次获取"
}
```

之后再调 → `410 Gone` + `{ "error": "already_installed" }`。

### 6.3 必须防住的漏洞（验收清单）

| # | 风险 | 防御 |
|---|------|------|
| 1 | **重复安装 / 重置超管** | DB 事务：`SELECT COUNT(*) FROM admin_users` + `install_state` 行级锁/唯一约束；已安装直接 410 |
| 2 | **竞态双请求** | 单事务 + `INSERT` 唯一用户名；第二请求失败不创建第二个超管 |
| 3 | **安装页长期暴露在公网** | 文档要求：安装前防火墙/仅本机；可选 env `SETUP_ALLOW_CIDRS=127.0.0.1,::1`（默认 release 建议仅 loopback，debug 可放宽） |
| 4 | **密码出现在日志/审计明文** | 审计只记 `action=install_bootstrap username=...`，**禁止**写 password；access log 不记 body |
| 5 | **弱密码** | `manual`：最少 12 位，含字母+数字；拒绝常见弱口令列表（含 `admin123456`）；`generate`：CSPRNG ≥16 |
| 6 | **前端可重复点** | 后端为准；前端成功后清状态并硬跳转登录 |
| 7 | **已有 env 管理员时再开向导** | 若 `admin_users` 已有行（含 `ensureDefaultAdmin` 种子），视为 **已安装**，不展示向导 |
| 8 | **伪造 installed=false** | status 只读 DB，客户端无法改；无「卸载」公开 API |
| 9 | **CSRF / 扫端口撞 bootstrap** | 同站；可选一次性 `setup_token` 写在**首次启动日志**（类似 random admin pass），bootstrap 必须带上 → 公网扫端口无法直接装 |
| 10 | **JWT 未配置就装完** | release 启动已 enforce JWT；安装完成后强制引导改密 + 检查 JWT_SECRET 非默认 |

**推荐默认安全组合（开源包）：**

1. 启动时若无 admin：**不自动创建**（改现有 `ensureDefaultAdmin` 策略为可选），只置 `install_state=pending`。  
2. 或保留现有「随机密码打日志」作为 **CLI 模式**；Web 向导与 CLI **互斥**：有任一 admin 即 installed。  
3. `SETUP_BOOTSTRAP_TOKEN`：首次启动生成并打印；bootstrap 请求头 `X-Setup-Token` 必须匹配；安装成功后 **删除/作废** token。  
4. 速率限制：`bootstrap` 每 IP 5 次/小时（防爆破 manual 密码）。

### 6.4 前端流程（`/ops/setup`）

1. 进入任意 `/ops/*` 前调 `setup/status`。  
2. `installed=false` → 只允许 setup 页（登录页可进但提示先安装）。  
3. 大按钮：**「一键生成管理员账号」**（`mode=generate`）。  
4. 展示用户名+密码 +「已复制」；勾选「我已保存密码」才可「进入登录」。  
5. **不提供**「重新生成」若已成功（后端已关）。  
6. 可选折叠：「我自己设密码」→ manual 模式 + 强度条。

### 6.5 与 `ensureDefaultAdmin` 的迁移策略

| 模式 | env | 行为 |
|------|-----|------|
| `INSTALL_MODE=auto`（兼容现状） | 默认可先保持 | 启动自动建 admin（随机或 `ADMIN_PASSWORD`） |
| `INSTALL_MODE=wizard`（开源推荐） | 文档默认 | 启动**不**建 admin；等 Web bootstrap |
| 已有 DB | — | 一律视为已安装，跳过向导 |

开源 README 默认写 `INSTALL_MODE=wizard` + `SETUP_ALLOW_CIDRS=127.0.0.1`。

## 8. 安全基线（开源发布前必过）

- [ ] 仓库无硬编码 `admin123456` / 内网 IP / 真实 HMAC  
- [ ] `.env` / `.push.env` / `data/*.db` 在 `.gitignore`  
- [ ] release：`JWT_SECRET` ≥16 随机，否则拒启  
- [ ] 安装完成后 setup 接口 410 + 无二次创建超管  
- [ ] 密钥 API 只脱敏读  
- [ ] 审计覆盖：install / login / change-password / update-secrets / update-brand  
- [ ] 管理 cookie/JWT：HttpOnly + SameSite（已有方向则保持）  
- [ ] 文档明确：安装期间勿把端口裸奔公网
